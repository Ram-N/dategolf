## Add DateLinks memory aids

Event: $ARGUMENTS

Follow `docs/06_datelinks_authoring_guide.md` exactly: it is the source of truth for group labels, tone and length. Read it first.

The aids live in the SQLite db. `src/data/datelinks.json` is generated by `npm run data:export`: **never edit it by hand**.

### Steps

1. **Find the event** in `src/data/events.json` by searching `name`, `aliases` and `description` for the key words in the argument. Use the event's `year` from the file, not the year the user typed.
   - One clear match → use its `id` verbatim.
   - Several plausible matches → list them and ask which one.
   - No match → stop and say so. Do not add aids for events that aren't in the db.
2. **Check for existing aids**: look up the id in `src/data/datelinks.json`. If it has some, show them and ask whether to keep them or replace them (`manage.py remove-memory-aids <id> --reason "..."`, then load the new ones).
3. **Research** the event and anchors. Use WebSearch to confirm any date you are not certain of: wrong dates are worse than no aid. Check that every person, invention and cause in an item existed at that date.
4. **Draft**: Look Back → Year of [YEAR] → Look Ahead → (Event Timeline only if the event has real phases). 2–3 items per group; skip any group without a strong anchor. Prefer anchors a student already knows, with concrete arithmetic ("add 20 years → …"). The `Year of` label is the event's year as `Year of 587 BCE` / `Year of 1962`.
5. **Write the batch** to `data/drafts/incoming/<YYYY-MM-DD>_claude_aids_<id>.json`:
   `{"origin": "ai_drafted:<model id>", "aids": {"<id>": {"groups": [{"label": "...", "items": ["..."]}]}}}`
6. **Load**: `uv run python tools/manage.py load-memory-aids <file>`. Fix and reload if it reports problems (nothing loads until every entry passes).
7. **Report** the anchors used, and tell the user the aids wait in the dashboard's **Review → Memory aids**. After approval: `npm run data:export`, `npm run data:compare`, then commit the db and the generated JSON.
